## 教训
1. **修复轮改动必须 commit 再 merge**：本轮三棵树修完没提交就 `git merge feat/X`，只合进了第一轮的提交，线上带着 390 弹层溢出（P0 级）上线，靠部署后真实浏览器复核才发现（第二遍 redeploy 才修好）。以后 fix 轮结束先 `git -C <wt> status --porcelain` 必须为空再 merge。
2. **deploy 绿 ≠ 线上对**：新交互的「打开态几何」必须部署后单独量（`.answer__fav-menu` 在 390 下 left/right vs viewport），断言里也要在打开态量溢出而不是关层后量。
3. 反向自检要挑「改动前必然为假」的判据（CSS 契约 computed maxWidth=none 这类），只靠 `scrollWidth>clientWidth` 会依赖种子数据的侥幸。
