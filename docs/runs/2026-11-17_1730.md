## 教训
1. **单点采样会误判「没有 loading 态」**：生产 API 200~300ms，`waitForTimeout(90)` 采样正好落在 loading 前后，连测三次都读到 `aria-busy=false`；用 `MutationObserver` 记录后才看到 t=84ms 的加载帧。今后验证瞬时状态一律用 MutationObserver 或 `waitForFunction`，不要用固定 sleep 取样。
2. **`page.route` 的 glob 里 `?` 不是字面量**：`**/api/questions?*` 匹配不到真实 URL，延迟没生效，反而让人以为链路没请求。用 predicate 函数 `(url) => url.pathname.includes("/api/questions")`。
3. **旧条目的 verify 可能指向不存在的脚本**：Z1046 的 `loadmore-feedback.mjs` 从未存在，`verify.sh` 直接 FAIL 0.05s，容易被当成「功能没做」。清账时要顺手核 verify 路径是否可执行。
4. **三棵树同时往 styles.css 末尾追加必冲突**：Z1135 与 Z1138 都在 EOF 追加，合并时手写冲突块又把 `<<<<<<<` 弄坏了一次（改完必须 `grep -c '<<<<<<<'` = 0 再 `tsc`/build）。
