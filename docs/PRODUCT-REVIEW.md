### 二、缺陷清单

#### P0-1 回答卡片没有「赞同/点赞」按钮，点赞链路完全不存在
- **现象**：`/question/1` 有 3 条回答，每条只有「229 人赞同」纯文本计数，卡片内没有可点元素（`button` 数=0、`a` 数=1 仅作者链接）。整页 `main` 内 button 数为 0。点赞无从谈起，计数 +1、状态变蓝都无法验证。
- **复现步骤**：`/zhihucopy/question/1` → 查看任一回答卡片底部 → 找不到赞同/反对按钮；接口层 `POST /api/votes {target_type:"answer",target_id:2,value:1}` 实测返回 `{"vote":1,"voteup_count":230}`，说明后端已就绪，前端未接入。
- **期望**：知乎式「▲ 赞同 230 / ▼」按钮，点击后计数 +1 且按钮文字变蓝，再点取消回退；未登录点击引导登录。
- **严重度**：P0（阻断主流程）
- **截图**：`/root/logs/rev2b-02-question-with-answers.png`

#### P0-2 回答卡片没有评论入口，评论链路完全不存在
- **现象**：回答卡片内无「评论 N」按钮、无评论列表、无输入框；`GET /api/comments?target_type=answer&target_id=2` 实测 200 且有 14 条数据，`POST` 发表也成功（id=325），前端未接入。
- **复现步骤**：`/zhihucopy/question/1` → 回答卡片 → 无任何评论入口，页面滚动到底也没有评论区。
- **期望**：回答底部「评论 N」→ 展开两级评论树 + 输入框，发布后立即出现在列表顶部并 +1。
- **严重度**：P0（阻断主流程）
- **截图**：`/root/logs/rev2b-02-question-with-answers.png`

#### P1-1 顶部搜索被完全忽略：无结果页、无空态，静默展示默认推荐流
- **现象**：输入「代码」回车后 URL 变为 `?q=%E4%BB%A3%E7%A0%81`，但内容区仍是默认推荐流 20 条，标题零命中，无「搜索结果」标题、无命中高亮、无「没有找到」空态。换不可能存在的词「zzzz不存在的词qqqq」结果同样是 20 条推荐流 —— 用户无法判断搜索是否生效。
- **复现步骤**：首页 → 顶部搜索框输入「代码」→ 回车 → 观察 URL 与列表；再搜「zzzz不存在的词qqqq」对比，两者列表一致。
- **期望**：`/?q=` 触发真实检索，标题「"代码" 的相关结果 · N 条」，无结果时给空态 + 推荐关键词；或搜索未上线就不要渲染可提交的搜索框。
- **严重度**：P1
- **截图**：`/root/logs/rev2-08-search.png`、`/root/logs/rev2b-05-search-impossible.png`

#### P1-2 通知页是占位空页，没有列表也没有未读角标

- **复现步骤**：已登录态访问 `/zhihucopy/notifications`（或点移动端底部「通知」）→ 只有一行占位文案。
- **期望**：通知列表（赞同/评论/关注分组）+ 未读高亮 +「全部标为已读」；角标随 `GET /api/notifications/unread-count` 更新，进入页面后清零。后端 `unread-count` 已可用（401 未带 token，带 token 返回 `{"count":0}`）。

### 二、缺陷清单（P0 / P1 / P2）

#### P0-1 移动端（390×844）没有任何搜索入口，搜索结果页也无法改词
- **实测**：390×844 下 `header` 高 53px，内部唯一 `input[placeholder="搜索问题、回答、用户"]` 与外层 `form.topnav__search`、`button[aria-label="提交搜索"]` 的 `getBoundingClientRect().width` 全为 **0**（`visible:false`），header 文本仅「知乎（仿） 提问 巡 …」；`nav.bottomnav` 5 项为 首页/发现/发布/通知/我，无搜索。
- **补充证据**：`/?q=代码` 深链在移动端能渲染「“代码” 的相关结果 · 9 条」，但页面上没有任何可见输入框（`inputVisible:false`），只有「取消搜索」——用户看得到结果、改不了词，等于只能退出。
- **影响**：移动端主流程（找内容）完全断链，且无 UI 层兜底。
- **复现**：390×844 打开 `/zhihucopy/` → 顶部与底栏均无搜索 → 手动访问 `/?q=代码` → 结果页无输入框。

#### P1-1 进入通知页不自动清零，刷新后仍未读
- **实测**：甲被乙回答后 `GET /api/notifications` 返回 `unread:1`；首页角标显示 `1`，`aria-label="通知，1 条未读"`。进入 `/notifications` 后页面头部为「1 条未读 · 共 1 条」，角标仍 `1`；F5 刷新后仍 `1`。只有点「全部标为已读」才变 `全部已读`、角标消失，再刷新保持 0。
- **影响**：读过的通知永远算未读，角标失去信号意义。
- **复现**：甲登录 → 乙回答甲的问题 → 甲看首页角标 1 → 进 `/notifications` → 角标仍 1 → 刷新仍 1。

#### P1-2 自己刚发布的回答，刷新后从默认排序里消失（内容像是没发出去）
- **实测**：问题 1 初始「8 个回答」、列表渲染 5 条。UI 发布回答后：toast「回答已发布」、计数 8→9、新回答立即在列表出现（`scrollY=538`）、编辑器清空。刷新后默认排序下 **新回答不在列表**（仍 5 条 + 「查看全部 9 个回答」），切「最新」才出现在第一条。默认排序按赞数，0 赞的新回答沉底且无任何「已排在后面」提示。
- **影响**：用户唯一的成功反馈在刷新后消失，是典型的「我是不是没发成功」。
- **复现**：登录 → `/question/1` → 写回答并发布 → 刷新 → 首屏 5 条里找不到自己的回答。

#### P1-3 他人主页没有关注按钮，关注链路在 UI 上不存在
- **实测**：`/u/978`（巡检丙）`main` 内 `button` 数为 0，仅显示「0 粉丝」「回答 0 提问 0」；API `POST /api/users/978/follow` 可用。因此「关注用户」只能靠接口，UI 无入口，`关注` tab 的内容供给也就无从建立。
- **复现**：登录后打开任意他人主页 `/u/<id>` → 找不到关注按钮。

#### P1-4 自己的回答、自己的评论都没有编辑/删除入口
- **实测**：自己发布的回答卡片按钮只有 `["赞同","反对","0 条评论","收藏","分享"]`；自己发的评论在 `.answer__comment` 内只有昵称/时间/正文，无「删除/编辑/回复」任何可点元素（页面级「编辑」是回答编辑器的 编辑/预览 切换，非内容编辑）。
- **复现**：登录 → 发一条回答/评论 → 卡片上找编辑或删除 → 无。

#### P1-5 404 归因错误且正文区无出口（问题/用户不存在都提示「检查网络」）
- **实测**：`/question/99999999` → 「问题不存在 请稍后重试；若持续失败，请检查网络后刷新页面。」`/u/99999999` → 「用户不存在 请稍后重试…」；`main` 内可点元素 **0 个**（`links: []`, `buttons: []`），只有全局导航可离开。
- **补充**：`/no-such-xyz` 文案是「页面不存在 回到首页继续浏览」，但「回到首页」并非链接（`main a` 为空），文案承诺了不存在的按钮。
- **复现**：打开任意不存在的 id → 读文案 → 找不到任何返回/搜索/提问 CTA。

#### P1-6 未登录点「写回答」只弹 toast，不跳登录、不带回跳
- **实测**：匿名在 `/question/1` 点「写回答」→ `scrollY` 仍 0，toast「登录后即可回答」×2，URL 不变，无 CTA。

#### P2-1 评论计数在展开后消失（数字本身是对的）
- **实测**：首条回答「18 条评论」→ 点击展开出 19 项、按钮变「收起评论」；发一条评论后收起显示「19 条评论」，刷新仍 19。展开状态下「N 条评论」这个数字被替换掉，是上一轮 P2 的原样复现。

#### P2-2 「反对」没有任何数字反馈

#### P2-3 搜索没有最小长度/标点过滤；`/search?q=` 直接 404

### 二、新发现的体验缺陷

**P0（阻断核心流程）：0 条。** 本轮未发现「注册后无法完成任一主流程」级别的问题；首页→详情→赞同→写回答→刷新这条主干全程可用。

**P1**

1. **P1-1 通知点了落到问题页顶部，不是那条回答**（上一轮遗留，仍未修）
   - 复现：A 提问 → B 回答 → A 打开 `/notifications` → 点任意一条。
   - 证据：`ntf__hit` 与 `ntf__title` 的 `href` 均为 `/zhihucopy/question/589`；点击后 `location.hash=""`、`scrollY=0`、`:target` 为 `false`、`[id^=answer-]` 元素在详情页有（脚本取到 `answer-2/answer-3/answer-378/...`），说明锚点已存在只是链接没带。
2. **P1-2 赞同、评论都不产生通知（通知只有「回答了你的问题」一类）**
   - 复现：A 提问并自答 → B 对该回答 `POST /votes {value:1}`（返回 200，`voteup_count:1`）→ B 再 `POST /comments`（返回 201，评论 id 380）→ 查 A 的通知。
   - 证据：`GET /notifications`（A 身份）`unread=0, total=0, items=[]`；页面同样为空态「暂时没有新通知」。即被赞同、被评论两条最常用的回流路径没有任何提示。
3. **P1-3 自己的评论无法删除、无法编辑**
   - 复现：登录后在他人回答下发表评论 → 悬停该行 → 找按钮。
   - 证据：该行 `outerHTML` 仅 `<li class="answer__comment"><span class="answer__comment-name">…</span><span class="answer__comment-time">刚刚</span><p class="answer__comment-body">…</p></li>`；行内 `button/a/[role=button]` 计数 0，`[aria-haspopup]` 0，悬停后可见按钮仍只有 1 个「发布」。接口侧其实有 `DELETE /comments/:id`（软删除、幂等），前端完全没有入口。
4. **P1-4 搜索结果页的「换个关键词」把用户踢回首页并清空关键词**
   - 复现：`/search?q=zzzz不存在的词` → 点「换个关键词」。
   - 证据：点击前 `url=/search?q=zzzz…`，点击后 `url=http://127.0.0.1:3030/zhihucopy`、顶栏 input `value=""`、`document.activeElement` 为 `BODY`。代码层面该按钮直接 `navigate("/")`（`exitSearch`），与「取消搜索」同一个动作——「换个词」语义被实现成「退出搜索」。
5. **P1-5 搜索只搜问题标题/描述，回答正文与用户搜不到，但 placeholder 承诺三者**
   - 复现：取 `/questions/1` 第 2 条回答正文片段「的观点：代码质量的核」搜索。
   - 证据：`h1="“的观点：代码质量的核” 的相关结果 · 0 条"`，页面「没有找到…」；而该字符串确实存在于回答正文（接口 `answers[1].content_md`）。同时结果页有 `TODO: type=answer|user|topic 分类 tab` 注释，界面上没有任何「只在问题里找」的说明。
6. **P1-6 错误页与个人主页空态仍是「无出口」**
   - `/question/999999`、`/u/999999`、`/nonexistent-xyz`：`main` 内 `a[href]` 0、`button` 0；文案仍是「问题不存在 / 请稍后重试；若持续失败，请检查网络后刷新页面」（归因错误）与「页面不存在 / 回到首页继续浏览」（「回到首页」不可点）。
   - 自己的空主页：`main` 内可点 3（「回答 0」按钮、「提问 0」按钮、「收藏 0」链接），空态只有一句「这个人还没有写过回答。」，没有「去回答 / 去提问 / 去关注话题」。

**P2**

1. **P2-1 评论发布后没有任何 toast**：发布后 `.toast` 元素计数 0（同页发回答会有「回答已发布」），评论只靠行内新增判断成功。
2. **P2-2 展开评论时计数数字被「收起评论」文案顶掉**：`1 条评论 → 收起评论`（数字消失），收起后才回到 `2 条评论`；同一控件两种语义、其中一种丢数字。
3. **P2-3「邀请回答」实为复制问题链接**：点击后 `[role=dialog]` 0，toast 内容是裸 URL `http://127.0.0.1:3030/zhihucopy/question/1`，没有任何邀请对象选择或「已复制」措辞（分享按钮同理，toast 直接显示 `…/question/1#answer-2`）。
4. **P2-4 浏览量同屏不一致（页面比接口少 1）**：首次进入问题页页面显示「0 次浏览」时接口已是 `view_count=1`；刷新后页面「2 次浏览」、接口 `3`。等于每次都要等下一次刷新才看到本次访问被计入。
5. **P2-5 公开内容里残留巡检/测试数据**：`/question/1` 首答评论区可见「评论回写验证 rv6-1794768473176…」「评论功能验证 comment-ui-2007」「真人review06kt3 的评论：…」「巡检甲2：第十轮巡检：这条评论能否删除？」；推荐流首条是空详情的「首屏性能复盘 6935 ？」（`detail_md=""`、`view_count=28`）。

### 五、方向建议

1. **一次改完「评论回路」三处，收益最高**：① 评论/赞同都写通知事件（`comment`、`agree`），通知行的链接带 `#answer-<id>`——详情页已有 `id="answer-N"`，只需在 `questionLinkFor()` 拼上锚点，落点问题当场解决（P1-1 + P1-2 同批）；② 评论提交后 toast「评论已发布」并把 `comment_count` 写回外层按钮，同时把按钮文案从「N 条评论 / 收起评论」拆成两个控件（计数常显 + 独立收起），解决 P2-1/P2-2；③ 自己评论行常显「删除」，直接接已有的 `DELETE /comments/:id`（P1-3）。
2. **搜索改成「原地续搜」而非「退出再进」**：结果页把顶部那条 `msearchbar` 输入框固定住并预填当前 `q`，「换个关键词」= `focus()` 该输入框 + `select()`，不要 `navigate("/")`；同时补 `type=answer|user|topic` 分段（接口已有 `/search`），或在标题旁注明「当前仅搜索问题」，避免 placeholder 承诺与实际范围不一致（P1-4 + P1-5）。
3. **给每类空态一个「下一步」出口**：错误页区分「不存在（404，给回首页/去提问）」与「网络失败（给重试）」，并把「回到首页」做成按钮；个人主页零回答时给「去回答问题」「去提问」；顺带清掉公开数据里的巡检残留（P1-6 + P2-5），这类文本对「这是不是真站点」的判断伤害比 UI 细节更大。

## 第十三轮（2026-11-16 04:2x，Z1044 上线后即验；线上真实浏览器）

范围：本轮新增的搜索分类（`/search?q=&type=question|answer|user`）——问题 / 回答 / 用户三段 tab、回答结果卡、用户结果行、空态与移动端。

### 一、上线即抓到 P0（本轮自己引入，已修）

| 步骤 | 期望 | 实测（旧构建） |
|---|---|---|
| `?q=代码&type=answer` 直达 | 20 张回答卡 | 通过 |
| 点 tab「用户 16」 | 切到用户结果 | **不通过：整站白屏**（`body.innerText.length=0`、`body.innerHTML=458`），控制台连报 `Cannot read properties of undefined (reading 'slice')` |
| 浏览器后退 | 回到回答结果 | 不通过：仍白屏 |

根因：`type` 随 URL 立刻变，`items` 仍是上一个 scope 的对象，`UserResultRow` 用 `u.nickname.slice(0,1)` 渲染问题对象 → 抛错；无 ErrorBoundary → React 卸载整棵树。**这暴露了验收漏洞：`search.mjs` 当时只断言 URL 与 `aria-selected`，没断言「页面还有内容」，所以 gate 全绿却上线了白屏。**

修复（Z1044b）：`itemsScope` 门控（scope 与数据不一致时走骨架，绝不旧数据配新渲染器）+ 行组件字段守卫 + 结果区 ErrorBoundary（中文错误卡 + 重试）+ e2e 真实点击四步并断言 `body>200ch`/`__errs===0`/卡型匹配。
